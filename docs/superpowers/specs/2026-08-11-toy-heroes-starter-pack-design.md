# Toy Heroes Starter Pack Design

## Goal

Add ten recognizable, kid-friendly starter characters as real, locally stored GLB models generated by an offline Apple Metal pipeline. Every model must be easy to select, manipulate, save, reload, and use in both editor and play mode.

## Character Set

The pack contains exactly:

1. Dinosaur
2. Unicorn
3. Robot
4. Knight
5. Wizard
6. Princess
7. Astronaut
8. Ninja
9. Puppy
10. Superhero

Existing primitive starter entries are upgraded in place when their identity already exists. Dinosaur, Unicorn, and Superhero are added as new starter entries. The picker must not show primitive and model duplicates of the same character.

## Visual Direction

The pack uses one cohesive toy-like style: rounded low-poly forms, readable silhouettes, saturated colors, friendly proportions, and no realistic weapons or frightening detail. Characters must remain recognizable at selector-tile size.

Each model has a distinct silhouette:

- Dinosaur: large head, short arms, strong legs, long tail, back plates.
- Unicorn: horse body, four legs, mane, tail, and one prominent horn.
- Robot: blocky torso, head screen, antenna, segmented arms and legs.
- Knight: armored body, helmet, plume, shield, and a short non-realistic toy sword.
- Wizard: robe, large pointed hat, beard, and staff.
- Princess: crown, rounded gown, hair, and friendly face shape.
- Astronaut: helmet, backpack, gloves, boots, and compact suit body.
- Ninja: masked head, tied headband, compact limbs, and no realistic weapon.
- Puppy: oversized head, floppy ears, four legs, and curled tail.
- Superhero: cape, chest emblem, boots, and confident upright pose.

The first version is static. It does not include skeletons, animation clips, facial animation, sound, particles, or alternate costumes.

## Generation Architecture

Generalize the existing Metal dragon generator into a reusable offline starter-model generator without changing the browser runtime dependency model.

A shared Metal kernel continues to generate transformed procedural primitives into GPU vertex buffers. Swift owns reusable part descriptors, per-character part lists, material definitions, triangle indices, GLB serialization, and model metadata extraction. A command accepts a character identifier or `--all`, producing one deterministic GLB per character under `public/models/starters/`.

The checked-in GLBs are the runtime artifacts. Metal, Xcode, and Swift are never required by the deployed application or normal non-macOS development.

Each GLB contains named anatomical/visual nodes and named PBR materials. All nondegenerate triangles must use outward winding, normals must be finite, accessors must be valid, and generation must be byte-for-byte deterministic.

## Asset and Performance Budgets

- Each GLB must remain under 300 KB.
- Each model must remain under 12,000 triangles.
- The complete ten-model pack must remain under 2.5 MB.
- Use local PBR factors and vertex/material colors; do not add external texture files.
- Selector previews continue using the bounded preview-canvas allocator, including retiring-context accounting and the reserved model capacity.
- Models load on demand; the selector must not preload all ten GLBs at application startup.

## Prefab and Runtime Metadata

Each model-backed `CharacterPrefab` includes:

- stable `id`, display `name`, description, and aliases;
- local `model_url`;
- tuned percentage `size`;
- exact `model_bounds` copied from the generated GLB;
- `model_origin_offset` that places the lowest point at the world/physics anchor;
- default color metadata for UI and AI responses.

The existing shared render contract uses these values for editor/play scale parity, grounding, and collision radius. Materials are cloned per runtime instance so appearance changes never leak between characters or into the GLTF cache.

Prefab matching prioritizes model-backed character aliases in compound prompts. For example, `friendly robot`, `wizard hero`, and `astronaut princess` must follow a documented deterministic priority rather than array order. When multiple distinct model characters are named, the last explicitly named character wins because it is normally the user's primary noun.

## Editor Experience

The ten characters appear in Add Character → Starters with their real model previews. Selecting a tile inserts a normal `character` object at the standard spawn. Existing move, rotate, scale, property, deletion, costume, and logic-block flows remain available.

Preview loading, errors, and WebGL allocation use the existing bounded lifecycle. A failed model preview displays a lightweight fallback inside the same leased Canvas. The selector remains usable while other previews wait for a lease.

## Play Experience

Play mode uses one scale owner, the same bounds/origin contract as the editor, and bounds-aware touch radius. Characters must appear at the same visible size and ground contact as in the editor. Static models do not claim or attempt animation clips.

## Error Handling

Generation fails with a character-specific message for unknown identifiers, unavailable Metal, invalid GPU output, invalid geometry, or GLB write errors. `--all` reports the failing identifier and exits nonzero without replacing previously valid committed assets with partial files.

At runtime, one missing or invalid GLB must be contained to its preview/object fallback without crashing the selector, editor, or other model instances.

## Validation

- Generator tests verify identifiers, `--all`, isolated temporary builds, deterministic output, size budgets, triangle budgets, accessors, finite values, outward winding, node names, and material names.
- Prefab tests verify all ten model URLs, bounds, offsets, tuned sizes, aliases, compound-prompt priority, and complete API response metadata.
- Render-contract tests verify scale parity, grounding, collision radius, independent material ownership, preview budgeting, and fallback containment.
- Production browser validation adds every model once, checks preview readability and initial scale, manipulates representative instances, enters play mode, and verifies a save/reload cycle.
- Stress validation opens/closes and scrolls the selector repeatedly with no WebGL-capacity warning or editor context loss.

## Out of Scope

This pack does not add animation, fire, combat systems, alternate colors, texture files, an asset marketplace, remote AI generation, database schema changes, or user-upload changes.
